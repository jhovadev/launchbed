# F1.7B — Guided Launchbed UI

Baseline: `88f8e06` (F1.7A.1 SSR hotfix on `main`). The generator, public request schema, dependency resolver, ZIP format, Gradle templates and Android tooling are unchanged.

## User journey

1. Choose one of four **generatable** presets via accessible radio cards. Five planned presets are shown as read-only coming-soon entries. Start on Compose Minimal, or choose Custom setup.
2. Give the app a project name and application ID. Namespace follows app ID until changed independently. SDK and package choices live in a native expandable details section; existing server validations remain authoritative.
3. Choose a Material 3 seed color. Less-used typography, corner radius and app theme options are in a separate details section.
4. Browse addons on demand. Search only among generatable addons. Preset-required addons are marked included and cannot be unchecked because the generator always adds them back.
5. Inspect the illustrative preview, check the file plan, or download the deterministic ZIP using the existing APIs. Preview adds Notes and Catalog illustrative screens but does not claim pixel fidelity or device validation.

## Design and accessibility

- Responsive at narrow mobile widths; preview moves beneath the form.
- Labels, radio groups, native details/summary disclosure and screen buttons with `aria-pressed`.
- `aria-live` messages and error summaries remain present.
- No new runtime dependencies, external font requests or analytics.
- Language stays English for this phase; i18n is postponed by project decision.

## Deployment contract

`deploy:smoke` requires `data-launchbed-ui="f17b"` in rendered HTML in addition to a working form, all APIs and two identical ZIP responses. Missing selector reports page title and requested origin so a stale or unrelated production deployment is distinguishable from a Solid SSR failure.

## Verification

```bash
node --test scripts/deployment/vercel-smoke.node.test.mjs
bun run typecheck
bun run check:astro
bun test packages tests
bun run build
bun run deploy:ssr-smoke
just vercel-build
```

When the above gates pass, review/commit/push normally, then verify the **Ready production deployment**, not just the most recent CI build:

```bash
LAUNCHBED_DEPLOY_URL='https://launchbed.vercel.app' bun run deploy:smoke
```

### Manual browser acceptance

- Keyboard-only: tab through preset cards, customize two identity fields, open advanced choices, toggle a non-required addon, inspect the file plan, download a ZIP.
- Verify `local-notes` and `catalog-ui` preview their corresponding *illustrative* screens; beta labels remain.
- Verify 360 px width and a desktop viewport, zoom 200%, dark preview, custom color, and validation errors.
- Verify selecting a new preset resets included addons but preserves project identity; required addon checkboxes cannot be deselected.
- Check that duplicate `/api/generate` requests with the same body yield identical bytes.

**Not verified by this change:** performance of the production browser, real-device Compose rendering, Vercel production deployment or Android instrumented tests.
