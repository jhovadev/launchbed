# F1.6B — Performance Baseline (incremental patch)

**Base:** F1.5 + F1.6A + F1.6A.1. No commits or pushes authorized.

## Scope

- Add an opt-in pure Bun benchmark harness for the four generatable presets, measuring actual materialization, ZIP packaging and ZIP verification phases. The harness cross-checks SHA-256 with the existing production generator on each sampled run.
- Add an opt-in Android Gradle benchmark: fresh generated project, debug assembly/JVM tests/lint, no-change repetition, artifact sizes, optional unsigned release. Only fixed build output directories are written; do not modify source templates or download SDK images.
- Add a pure Node test suite for CLI validation and statistics, executable without Bun or Android SDK.
- Reports are JSON under ignored `build/performance/`, with no fabricated values and no CI timing gates.

## Verification and acceptance

```bash
node --test scripts/performance/metrics.node.test.mjs
bun run typecheck
bun test packages tests
bun run check:astro
bun run templates:check
bun run build
bun run scripts/performance-baseline.ts generator
bun run scripts/performance-baseline.ts android --all
```

Treat any command not executed as **NOT RUN**, not PASS. For Android, an unavailable SDK produces a **BLOCKED** JSON report and exit 78. A successful Gradle exit without a debug APK is FAIL.

## Runtime limits

This change does not instrument Jetpack Compose or Android startup. `noChangeRepeat` is not a source-change incremental compilation benchmark; shared Gradle caches can skew the first build. No Baseline Profiles, fake Perfetto traces, UI screenshots or device metrics are produced. Do not promote addons based on these measurements.
