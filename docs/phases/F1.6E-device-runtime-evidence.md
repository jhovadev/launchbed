# F1.6E — Device Runtime Evidence & Instrumentation Hardening

**Base:** F1.6D (`F1.6D-optimized-release-privacy.zip` applied). No changes to generated Android templates, dependency versions, APK artifacts, or generator logic.

## Motivation

The F1.6D release audit passed static R8/backup/ELF/ZIP checks on four unsigned APKs, but `release-check` correctly returned `BLOCKED` (78) because the three UI/storage presets had `instrumented=NOT RUN`.

This incremental patch helps execute instrumented tests safely and makes it harder for stale or compile-only evidence to be mistaken for real device testing.

## Changes

- `just runtime-device-check` validates **one explicit authorized** ADB device, Android boot completion (`sys.boot_completed=1`), minSdk 26 and ABI, without writing to or installing on the device.
- `android-test` and direct `test --run` refuse to start Gradle when device preflight fails.
- `am instrument -w` uses the normal runner summary (not `-r` raw mode), matching the existing strict `OK (N tests)` / `INSTRUMENTATION_CODE: -1` parser. [Android CLI testing](https://developer.android.com/studio/test/command-line).
- Release evidence is written separately to ignored `build/runtime-verification/device-report.json`. Another compile-only smoke cannot overwrite it. An actual `--run` (including failures) overwrites prior device evidence.
- Device report schema v2 includes executed test count, successful APK installation checks, API/ABI, hashed serial, and a source fingerprint. `release-check` rejects missing/old/wrong-kind/duplicate evidence.
- Correct a misleading Room Bun test name: Room is currently `beta`, **not stable**, while still generatable.

## Local validation commands

```bash
node --test scripts/runtime/*.node.test.mjs
node --test scripts/integrity/gates.node.test.mjs
just check
just release-check  # expected BLOCKED=78 until real device instrumentation
```

Then, on a host with Android SDK/JDK and an authorized device or emulator:

```bash
just runtime-devices
ANDROID_SERIAL=emulator-5554 just runtime-device-check
ANDROID_SERIAL=emulator-5554 just android-test
just release-check
```

Substitute the actual serial. `android-test` compiles all four presets, but only the three with instrumented sources must report actual executed tests. It writes `report.json` and `device-report.json` under `build/runtime-verification/`.

## Acceptance

1. Node parser/integrity tests pass.
2. Patch applies cleanly on F1.6D without changing other files.
3. Compile-only report never constitutes release device evidence.
4. An actual device run can validate all three instrumented presets, but if no device is available, results remain NOT RUN/BLOCKED.
5. Gradle/Android instrumentation tests require the user's Android environment. No PASS is claimed for device runtime until they run.

No commits, pushes, SDK downloads or hidden ADB operations are performed by this patch's installer.
