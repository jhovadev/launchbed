# F1.6F — CLI AVD provisioning (no Android Studio)

## Why

F1.6E runtime builds and release checks passed, but the example serial `emulator-5554` was **not connected**. `release-check` returning `BLOCKED` (78) is correct; no instrumentation was executed. The repository already supports `just emulator-list`, `just emulator-start` and `just runtime-device-check`, but had no safe way to create an AVD from the CLI.

## Existing AVD (fastest path)

```bash
unset ANDROID_SERIAL  # do not pin an emulator-5554 that does not exist
just runtime-doctor
just emulator-list
AVD_NAME=MY_INSTALLED_AVD just emulator-start
just runtime-devices
# Use the actual serial shown by ADB, after the device finishes booting.
ANDROID_SERIAL=emulator-5554 just runtime-device-check
ANDROID_SERIAL=emulator-5554 just android-test
just release-check
```

Change both AVD name and serial to real values. **AVD names and ADB serials are different identifiers.** `emulator-start` only requests startup and does not assert boot completion.

## No AVD installed

The newer official Android CLI also supports `android emulator list`, `android emulator create` and `android emulator start`. If it is installed, those commands are an option. Android Initializr provides a predictable command-line-tools fallback using `sdkmanager` and `avdmanager`:

```bash
just runtime-doctor
just emulator-images
# Only if the desired image is not already installed, explicitly download via the official SDK manager.
# sdkmanager --list | grep system-images
# sdkmanager --install 'system-images;android-36;google_apis;x86_64' 'emulator'
# sdkmanager --licenses
AVD_NAME=Initializr_API36 \
  AVD_IMAGE='system-images;android-36;google_apis;x86_64' \
  just emulator-create
AVD_NAME=Initializr_API36 just emulator-start
just runtime-devices
```

The image ID above is **illustrative**. Select a version and architecture that the official SDK manager actually offers for your machine. Creation requires a locally installed compatible image, never initiates downloads or license acceptance, does not overwrite existing AVDs, and validates names as restricted ASCII strings. The fallback uses `avdmanager`, which Android documentation labels legacy in favor of the newer Android CLI.

## Evidence and safety

- `just emulator-images`: read-only, lists installed system images.
- `just emulator-create`: explicit mutation; requires `AVD_NAME` and `AVD_IMAGE`, checks exact installed image and rejects existing names.
- `just emulator-start`: existing explicit action; no automatic device selection.
- `just android-test`: uses one explicitly selected, authorized, fully booted serial and runs real instrumentation.
- `just release-check`: remains BLOCKED until the three test suites genuinely pass and evidence is current.
- No changes to Gradle, APK, templates, or runtime/release evidence rules.

On Linux, check `/dev/kvm` and `emulator -accel-check` when emulator startup fails. A physical Android device with USB debugging is another option; select its actual ADB serial, never the example `emulator-5554`.

## Validation

`node --test scripts/runtime/avd-provision.node.test.mjs` tests input rejection, image table parsing, and safe creation arguments. Actual AVD creation and instrumented execution are **NOT RUN** in an environment without Android SDK/AVD; no runtime PASS should be inferred.
