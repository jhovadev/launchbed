# F1.6A — Runtime Verification and Device Safety

**Source baseline:** F1.5 archive `launchbed-F1.5-source.zip` (2026-11-14).  No original `.git` directory included.

## Goals and changes

- Add `scripts/android-runtime.ts` to generate and independently compile each working preset: `compose-minimal`, `compose-starter`, `local-notes`, and `catalog-ui`.
- For presets containing `androidTest`, compile the instrumentation APK by `:app:assembleDebugAndroidTest`. **Compilation is not execution**.
- For `--run`, select a single *authorized online* device through ADB (with `--serial` / `ANDROID_SERIAL` if ambiguous), install the APK and test APK explicitly with `adb -s`, then run `am instrument -w -r` on that exact serial. A successful runner must report `OK (N tests)`, N > 0, and `INSTRUMENTATION_CODE: -1`. Save raw runner output.
- Verify nonzero JVM JUnit XML test counts with zero failures, errors, or skipped results after Gradle completes. Fail closed when reports or APKs are missing.
- Emit `build/runtime-verification/report.json`, separating PASS, FAIL, BLOCKED and NOT RUN.
- No Android Studio, automatic downloads, credential handling, or preselected physical devices.
- Extend Room instrumented tests to cover reactive Flow emissions and file-based DB close/reopen. Retain the original in-memory DAO tests.
- Introduce small Compose instrumentation smoke tests for Navigation, Dashboard, Settings, Notes and Catalog via addon contributions, without adding UI-test libraries to the minimal project.
- Correct two compiled-but-unreachable presets: **Local Notes** now opens Notes; **Catalog UI** registers Catalog in Navigation 3 and opens it. Prefer keeping these repairs with runtime readiness rather than declaring the presets production-ready.
- Validate `ANDROID_SERIAL` against ADB in generated Bash and PowerShell scripts instead of trusting a stale or unauthorized serial.

## Commands

```bash
just runtime-parser-test        # pure Node tests, no Bun / SDK / device
just runtime-doctor             # read-only
just runtime-devices            # adb devices with states
just emulator-list              # installed AVDs only
AVD_NAME=Pixel_API_35 just emulator-start    # opt-in, no auto-download
ANDROID_SERIAL=emulator-5554 just emulator-stop
just android-runtime-compile    # compile all presets; NOT RUN instrumentation
ANDROID_SERIAL=emulator-5554 just android-test
ANDROID_SERIAL=emulator-5554 just android-test-room
ANDROID_SERIAL=emulator-5554 just android-test-ui
```

Direct equivalents:

```bash
bun run scripts/android-runtime.ts test --preset local-notes
bun run scripts/android-runtime.ts test --preset local-notes --run --serial emulator-5554
```

For Windows, use `bun run scripts/android-runtime.ts ...` directly from PowerShell. The generated projects still include their own `.ps1` scripts. `--run` will not guess when more than one device is online. `emulator-start` requires an already installed AVD; this phase does not implement AVD creation or system-image provisioning.

## Gates, limitations and expected statuses

- Running `bun run typecheck`, `bun test packages tests`, `bun run templates:check`, `bun run check:astro`, and `bun run build` requires the repository's Bun dependencies.
- Running the Android runtime smoke requires installed Android SDK + JDK 21 and the generated Gradle wrapper; it may need dependency downloads.
- A test APK with no device available is **NOT RUN**, not PASS. A real instrumentation PASS requires explicit `--run`, installation and runner summary.
- The Compose tests added in this patch are smoke coverage for screen rendering, not full end-to-end navigation, CRUD or process-death restoration. Do not promote Room and UI addons to stable based on these tests alone.
- Emulator performance is not representative of real device performance; benchmarks belong to F1.6B.
- `build/runtime-verification/` is ignored by Git. No user files outside this controlled build directory are modified.

## Reproducing patch delivery

Archive was supplied without `.git`. The `.patch` is relative to the complete **F1.5 source tree in the ZIP**, not directly to commit `a316f53` alone. Earlier F1.x patches must be present/applied first. The installer verifies the patch checksum and invokes `git apply --check` before applying anything. It does not commit or push.
